# Мануал по CVE Monitor Bot

Внутренняя документация «для себя»: что это, как устроено, как работает каждая
часть, как запускать и что делать, когда что-то идёт не так.

---

## 1. Что это и зачем

Telegram-бот, который избавляет от ручного мониторинга уязвимостей на
[nvd.nist.gov](https://nvd.nist.gov). Он сам ходит в базу **NVD** (National
Vulnerability Database), достаёт свежие CVE, обогащает их данными об эксплуатации
и отдаёт в Telegram — либо по команде, либо сам (авто-уведомления).

**Стек:** Python 3.12, `python-telegram-bot` (асинхронный), `requests`,
`python-dotenv`. Запускается в Docker.

---

## 2. Архитектура и поток данных

```
                    ┌──────────────────────────────────────────┐
   Пользователь     │                cve_bot.py                 │
   в Telegram  ───► │                                           │
   /scan /cve ...   │  CommandHandler ─► cmd_*()                │
                    │        │                                  │
                    │        ▼                                  │
                    │  fetch_* ──► _nvd_get() ──────────► NVD API│
                    │        │      (ключ, retry, пагинация)     │
                    │        ▼                                   │
                    │  parse_cve()  (нормализация)               │
                    │        ▼                                   │
                    │  enrich_cves() ──► get_kev_ids() ─► CISA KEV│
                    │        │      └──► get_epss_scores() ► EPSS │
                    │        ▼                                   │
                    │  format_cve_list()  (HTML, бейджи, сорт.)  │
                    │        ▼                                   │
                    │  send_parts() ─────────────────► Telegram  │
                    │                                           │
                    │  JobQueue ─► check_new_cves() (по таймеру) │
                    └──────────────────────────────────────────┘
```

Поток для любой команды: **получить сырые данные из NVD → распарсить → обогатить
KEV/EPSS → отформатировать → отправить**.

---

## 3. Внешние источники данных

| Источник | URL | Что даёт | Лимиты |
|---|---|---|---|
| **NVD** | `services.nvd.nist.gov/rest/json/cves/2.0` | сами CVE, CVSS, описания | 5 запр./30с без ключа, **50 с ключом** |
| **CISA KEV** | `cisa.gov/.../known_exploited_vulnerabilities.json` | список активно эксплуатируемых CVE | без лимита, кэшируется на 6ч |
| **EPSS** | `api.first.org/data/v1/epss` | вероятность эксплуатации (0–1) | батчами по 100 CVE |

## 4. Разбор кода `cve_bot.py` по блокам

### 4.1. Конфигурация (из `.env`)
Читается через `os.getenv` после `load_dotenv()`:
- `TELEGRAM_TOKEN` — токен бота (обязателен, иначе `main()` падает с понятной ошибкой);
- `TELEGRAM_CHAT_ID` — куда слать авто-уведомления;
- `CVSS_THRESHOLD` (7.0) — порог критичности;
- `HOURS_BACK` (24) — глубина «свежести»;
- `NVD_API_KEY` — ключ NVD (опционально);
- `CHECK_INTERVAL_MIN` (0) — период авто-проверки в минутах (0 = выключено).

### 4.2. Слой NVD — `_nvd_get(params)`
Единая точка всех запросов к NVD. Делает три важные вещи:
1. **Авторизация** — если задан `NVD_API_KEY`, добавляет заголовок `apiKey`.
2. **Retry с бэкоффом** — до 3 попыток с паузами 6/12/18с при сетевой ошибке.
3. **Пагинация** — листает по `startIndex`, пока не соберёт все `totalResults`
   (страница до 2000 записей).

Поверх него три функции:
- `fetch_recent_cves(hours)` — по диапазону дат публикации (`/scan`, авто-проверка);
- `fetch_cves_by_keyword(keyword)` — поиск по всей базе (`/filter`);
- `fetch_cve_by_id(cve_id)` — одна конкретная CVE (`/cve`).

### 4.3. Парсинг — `parse_cve(item)`
Превращает «сырой» JSON NVD в плоский словарь: `id`, `score`, `severity`,
`description` (обрезка до 250 симв.), `published`, `url`, `raw_description`.
**Важная деталь:** CVE без CVSS (статус *Awaiting Analysis*) **не выбрасывается** —
у него `score = None`, и он показывается с пометкой «оценка ожидается». Это самые
свежие уязвимости, их терять нельзя.

### 4.4. Обогащение — `enrich_cves(cves)`
- `get_kev_ids()` — тянет каталог CISA KEV и кэширует множество id на 6 часов
  (`_kev_cache`), чтобы не дёргать его на каждый запрос.
- `get_epss_scores(ids)` — берёт EPSS батчами по 100.
- Проставляет каждому CVE поля `kev: bool` и `epss: float|None`.

### 4.5. Дедупликация — `load_seen()` / `save_seen()`
Чтобы авто-уведомления не слали одно и то же. Множество уже отправленных id
хранится в `seen_cves.json`. Файл ограничен `SEEN_LIMIT = 10000` последними id,
битый/отсутствующий файл воспринимается как пустой набор.

### 4.6. Форматирование — `format_cve_list(cves, title, max_items=8)`
- **Сортировка:** сначала KEV (активно эксплуатируемые), потом по CVSS, потом по EPSS.
- **Экранирование HTML** (`html.escape`) — иначе символы `<`, `>`, `&` в описании
  ломают разбор `parse_mode=HTML` в Telegram.
- **Бейджи:** 🚨 CISA KEV, 📈 EPSS.
- **Разбивка** длинных сообщений на части ≤ 4000 символов (лимит Telegram).

### 4.7. Команды (`cmd_*`)
Каждая: шлёт «⏳ …», вызывает нужный `fetch_*` (в отдельном потоке через
`asyncio.to_thread`, чтобы не блокировать event loop), фильтрует по порогу,
обогащает, форматирует, отправляет.

### 4.8. Авто-уведомления — `check_new_cves()` + JobQueue
Регистрируется в `main()` только если `CHECK_INTERVAL_MIN > 0` **и** задан
`TELEGRAM_CHAT_ID`. По таймеру: берёт свежие CVE → отсекает уже отправленные
(по `seen`) → обогащает → шлёт новые в чат → дописывает их в `seen_cves.json`.

### 4.9. Запуск — `main()`
Проверяет токен → создаёт `Application` → регистрирует обработчики команд и кнопок →
(опционально) ставит джобу в JobQueue → `run_polling()`.

## 5. Команды бота

| Команда | Что делает под капотом |
|---|---|
| `/start` | приветствие + inline-кнопки (вызывают те же команды) |
| `/help` | список команд + легенда бейджей |
| `/scan` | свежие CVE за `HOURS_BACK`ч с CVSS ≥ порога (+ без оценки) |
| `/critical` | то же, но только CVSS ≥ 9.0 |
| `/filter <слово>` | поиск по **всей** базе NVD через `keywordSearch` |
| `/cve <id>` | карточка по id; валидирует формат `CVE-ГГГГ-ЧИСЛО` |
| `/status` | порог, интервал авто-проверки, наличие NVD-ключа, время последнего скана |

## 6. Конфигурация `.env`

См. таблицу в `README.md` и шаблон `.env.example`. Минимум для запуска — только
`TELEGRAM_TOKEN`. Для авто-уведомлений добавить `TELEGRAM_CHAT_ID` и
`CHECK_INTERVAL_MIN > 0`. Для снятия лимитов NVD — `NVD_API_KEY` (не забыть
**активировать** ключ по ссылке из письма NVD).

## 7. Эксплуатация (Docker)

Бот живёт в Docker с политикой `restart: unless-stopped` (поднимется сам после
перезагрузки). `seen_cves.json` хранится в volume `cve-data`, поэтому переживает
пересоздание контейнера.

```bash
# собрать и запустить (из папки проекта)
docker compose up --build -d

# логи в реальном времени
docker compose logs -f

# статус
docker compose ps

# остановить / перезапустить
docker compose stop
docker compose restart

# полностью убрать (контейнер + сеть, volume остаётся)
docker compose down
```

Локальный запуск (для отладки, **не одновременно** с контейнером — см. п.9):
```bash
pip install -r requirements.txt
python cve_bot.py
```

## 9. Траблшутинг

| Симптом | Причина | Решение |
|---|---|---|
| `Conflict: terminated by other getUpdates request` | **два экземпляра** опрашивают один токен (Telegram разрешает только один) | оставить ровно один: остановить лишний контейнер / убить `python cve_bot.py`. Нельзя гонять Docker и локальный запуск одновременно |
| `Invalid apiKey` / HTTP 404 от NVD | ключ не активирован или с опечаткой | активировать по ссылке из письма NVD; проверить, что ключ — UUID 36 символов одной строкой `NVD_API_KEY=...` |
| Долгие паузы и 0 результатов | сработал retry-бэкофф (NVD недоступен или 429 от лимита) | подождать; добавить `NVD_API_KEY` для поднятия лимита |
| `[FATAL] Не задан TELEGRAM_TOKEN` | пустой `.env` | вписать токен от @BotFather |
| Telegram-ошибка `can't parse entities` | спецсимволы в HTML | уже решено экранированием; если всплыло — проверить, что текст идёт через `format_cve_list` |
| Авто-уведомления не приходят | `CHECK_INTERVAL_MIN=0` или нет `TELEGRAM_CHAT_ID` | задать оба; в логах должно быть «Авто-уведомления включены» |
| Первый прогон авто-уведомлений шлёт «всё» | `seen_cves.json` пуст | это нормально, дальше только новые |

## 10. Безопасность

- Секреты (`TELEGRAM_TOKEN`, `NVD_API_KEY`) — только в `.env`, который в `.gitignore`
  и **не попадает в git**. В репо — лишь `.env.example`.
- Логи `httpx` приглушены до WARNING, чтобы токен не светился в URL запросов.
- В Docker секреты передаются через `env_file`, не зашиты в образ.

## 11. Идеи для развития

- Подписки нескольких чатов (`/subscribe`), а не один `TELEGRAM_CHAT_ID`.
- Фильтр-подписки по продукту/вендору (только `apache`, только `windows`).
- Источники помимо NVD (GitHub Security Advisories, OSV).
- Хранение в SQLite вместо JSON для seen + история.
- Метрики/healthcheck для Docker.
